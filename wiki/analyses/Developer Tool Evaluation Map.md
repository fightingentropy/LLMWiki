# Developer Tool Evaluation Map

The development collection contains many plausible tools but fewer records of actual outcomes. The useful next step is to connect a saved item to a concrete task and record what happened. This is a synthesis of [[Developer_Resources]], [[AI Agents]], [[Setup]] and the three linked bookmark collections, not a ranking of current products.

## Start with the job

- **Interface work:** choose a real screen and compare readability, interaction, accessibility and maintenance. [[Design_and_Aesthetics]] and [[Bookmarks - Design & Frontend]] supply references.
- **Agent work:** use a bounded task with visible inputs and a checkable output. Measure the corrections required and the user's supervision time. [[AI Agents]] supplies the permission and workflow questions.
- **Local utilities:** test the everyday path, restart behaviour, export and removal. [[Bookmarks - Developer Tools]] supplies candidates.
- **Hosted services:** identify the data leaving the device, recurring cost, failure behaviour and exit path. [[Digital Security]] connects access and data handling.

## One evaluation record

Write the task, candidate, version/date, current baseline, sample input, outcome, elapsed effort and what failed. Link the original bookmark. Include a screenshot or saved output only when it proves something the description cannot.

A useful comparison changes one thing at a time: same task and acceptance criteria, different tool. A benchmark screenshot or release claim can suggest a trial; it does not replace that trial.

## Decision

Choose one of: adopt for this job; keep as a specialist option; investigate a specific gap; or retain only as a reference. Record the reason and the condition that would change the decision. Preserve the bookmark regardless of the adoption decision, following [[Personal Knowledge Management]].
